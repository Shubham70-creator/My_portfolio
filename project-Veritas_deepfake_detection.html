Veritas — Deepfake Detection Platform

A full-stack platform that analyzes images, videos, audio and live webcam sessions for signals of manipulated or synthetic media, built by a team of five.

Overview

Veritas is a full-stack platform for checking whether an image, video, audio clip or live webcam session shows signs of being manipulated or synthetic. Instead of a simple yes or no, every result comes with one of five confidence bands: REAL, Possibly Real, Uncertain, Possibly Fake and FAKE. The project was built by a team of five, and it is packaged as a deployment-ready application.

What the Platform Does

  • Image, video and audio analysis: users upload a file and get a prediction, with file type and size validation.
  • Live webcam detection: frames are analysed in real time over a WebSocket connection.
  • User accounts: email/password signup and login, plus Google Sign-In, using JWT authentication.
  • Prediction history: every user can see their own past results, and their files stay private to them.
  • Usage plans: five free checks by default, with weekly, monthly and annual plans through Razorpay.
  • Admin dashboard: metrics and a user overview for the admin.
  • Deployment support: health and readiness endpoints, environment-based configuration and a Render Blueprint for the backend and frontend.

Tech Stack

  • Frontend: React, Vite, Tailwind CSS
  • Backend: FastAPI, WebSocket
  • Database: PostgreSQL with SQLAlchemy
  • Image / video model: PyTorch, MobileNetV2
  • Audio model: MobileNetV2 trained on mel-spectrogram images
  • Face processing: MediaPipe, with an OpenCV Haar cascade fallback
  • Extra video signals: rPPG and lip-sync correlation
  • Auth and payments: JWT, bcrypt, Google Sign-In, Razorpay

How the Detection Works

  1. The user uploads a file or starts a live webcam session from the React interface.
  2. Faces are found and cropped using MediaPipe, with OpenCV as a fallback if MediaPipe fails.
  3. The trained MobileNetV2 model predicts how likely the media is to be fake. For audio, the sound is first converted into a mel-spectrogram image and then classified the same way.
  4. For video, two supporting signals are added: rPPG (a pulse-like signal from the face) and lip-sync correlation.
  5. The signals are combined in a conservative ensemble, with weights of 90% CNN, 5% rPPG and 5% lip-sync, and the result is mapped to one of the five confidence bands.

My Role

We were five people on this project and the work was shared across the team. My main responsibilities were the model training and the frontend, and I also worked a little on almost every other part of the project.

Model training

  • Worked on the training pipeline: downloading the datasets, building the data manifests and training the detector.
  • Trained the MobileNetV2-based image and video detector in PyTorch.
  • Worked on the audio detection model, which uses mel-spectrogram images.
  • Evaluated the model and kept the validation results as experiment results instead of claiming real-world accuracy.

Frontend

  • Built the React + Vite + Tailwind CSS interface.
  • Created the pages for login and signup, the dashboard, upload and results, prediction history, live webcam detection and the upgrade page.
  • Connected the frontend with the FastAPI backend and the WebSocket live detection.

Other areas

  • Helped in integrating the model with the backend and in testing the full flow across the project.

What I Learned

  • How a full machine learning training pipeline works, from collecting data and making manifests to training and evaluating a model.
  • How transfer learning with MobileNetV2 helps, and how to turn audio into mel-spectrograms so that an image model can classify it.
  • How to build a real product interface in React and connect it with a Python backend, including real-time WebSocket communication.
  • How to work in a team of five: dividing the work, using Git and GitHub together, and joining the model, backend and frontend into one application.
  • Why a detector should not claim 100% certainty, and why showing confidence bands is more honest than a plain real or fake label.

Challenges

  • Keeping live webcam detection smooth while the model runs on incoming frames.
  • Making the model work reasonably across different faces, lighting and media quality.
  • Joining the work of five people into one application with a common structure for the model, backend and frontend.

Limitations and Honest Notes

  • The platform deliberately does not claim 100% certainty, which is why it uses five confidence bands.
  • The trained image and video detector is MobileNetV2-based. rPPG and lip-sync are supporting signals, not independently validated deep-learning detectors.
  • The validation results are experiment results from the project and should not be taken as a universal real-world accuracy guarantee.
  • For a real production rollout, uploaded files should be stored in durable private object storage instead of a temporary web-service filesystem.
