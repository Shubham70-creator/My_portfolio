Smart Attendance System Using Face Recognition

A Python desktop application that uses a webcam, computer vision and face recognition to take student attendance automatically.

The Problem

In a traditional classroom, the teacher marks attendance by hand. This takes time during the lecture and it also allows proxy attendance, where one student marks attendance for another. I wanted to reduce this manual effort and make the process faster and more convenient.

What I Built

I built a Smart Attendance System that uses OpenCV and the Local Binary Patterns Histograms (LBPH) algorithm to recognise registered faces through a webcam. When a registered face is recognised, the system records the student's ID, name, date and time in an attendance CSV file. Everything is controlled from a graphical interface made with Tkinter.

Features

  • Student registration: register a student with a unique ID and name.
  • Face image capture: capture the student's face images from the webcam.
  • Face detection: find faces in each camera frame using the Haar Cascade classifier.
  • Model training: train the LBPH recogniser on the captured images.
  • Face recognition: identify registered students in the live camera feed.
  • Automated attendance: record ID, name, date and time for every recognised student.
  • CSV storage: keep student details and attendance records in CSV files that open easily in Excel or Google Sheets.
  • Local processing: all webcam images are processed on the computer itself, with no cloud service.

Tech Stack

  • Python: main programming language
  • OpenCV: face detection, image processing and recognition
  • LBPH: face recognition algorithm
  • Haar Cascade: face detection
  • Tkinter: graphical user interface
  • NumPy: image array processing
  • Pandas: handling tabular data
  • CSV files: student and attendance record storage

How It Works

  1. Register: the user enters a student ID and name and clicks Take Images.
  2. Capture: the webcam captures the student's face images and saves them in the training folder.
  3. Train: the application processes the saved images and trains the LBPH model. The trained model is saved as Trainner.yml.
  4. Detect: when attendance starts, the webcam opens and the Haar Cascade finds the faces in every frame.
  5. Recognise: each detected face is compared with the trained model to find out which registered student it is.
  6. Record: the student's ID, name, date and time are saved in the attendance CSV file.

Why LBPH and Haar Cascade

LBPH describes the local texture patterns of a face as numerical histograms and compares them with the trained data. I used it because it works on grayscale images, it is light enough for a small application, it is available in OpenCV, and it runs locally without any cloud service.

The Haar Cascade only detects where a face is in the frame. The recognition model then decides whose face it is. These are two different steps: detecting a face does not identify a person.

My Role

This was a personal project, so I did all of it myself: planning the workflow, writing the registration and image capture, building the Tkinter interface, training the LBPH model, writing the real-time recognition and attendance recording, and testing and debugging the whole application.

What I Learned

  • How face detection and face recognition work, and how they are different from each other.
  • How to preprocess images, for example converting them to grayscale, and how to train an LBPH face recognizer with OpenCV.
  • How to build a desktop application with a Tkinter interface.
  • How to store and handle structured data with CSV files, Pandas and NumPy.
  • How to join several parts (GUI, camera, training and storage) into a single working application.
  • How to debug real problems like wrong file paths, library conflicts and runtime errors.

Challenges

  • The cv2.face error: the LBPH recogniser needs the opencv-contrib-python package, and conflicting OpenCV installations can break it.
  • Getting training to work: the images, file paths and file names had to match exactly what the training code expected.
  • Making sure that the camera opens properly and that recognised students are recorded correctly.

Limitations and Future Improvements

  • The system does not have liveness detection yet, so in theory a photograph or video could be used to fool it. Adding it is my main next step.
  • Attendance is stored in CSV files. A database like SQLite or MySQL would be better for larger use.
  • Recognition can be improved in different lighting conditions.
  • Duplicate attendance should be prevented across multiple sessions.
  • Planned additions: attendance reports with date filters, Excel and PDF export, admin login and a more modern interface.

Privacy

Face images are sensitive personal data. This project is meant for learning purposes, and anyone using a system like this should get proper consent, restrict access to the images and attendance records, and follow data-protection rules.
